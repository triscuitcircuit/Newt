# Self-contained, self-launching Godot export

**Status: implemented.** `newtd` bootstrap, `tools/bundle-dylib-closure.py`, standalone `bundle` mode, and `addons/newt_bridge/export_plugin.gd` are in place, with hardware-free coverage in `tests/session_manager_test.py` (bootstrap `run`, standalone bundle launch into private state, no lingering manager). (Originally mirrored into the Python reference manager too; that implementation has since been removed and `newtd` is the only manager.) Still outstanding: the on-device check (real Monado/MoltenVK export of `examples/godot-showcase`, Quest over USB, side-by-side with a system-wide install). One design detail changed during implementation — the dashboard stub: see §2.

## Context

Right now a Godot export is receive-only with respect to Newt. `addons/newt_bridge/session.gd`'s own comment says it plainly: *"Standalone games without a token use their own launcher/runtime configuration and do nothing here."* `NEWT_LAUNCH_TOKEN` only ever gets set by something external that already called `prepare`/`launch` first — the editor's Play button (`plugin.gd._build()`), a `newt run` CLI call, or a host like Pippin. A double-clicked export, run with nothing else around it, never touches Newt at all.

`newtd bundle` (`daemon/newtd.mm`'s `RunBundle`) already proves the right mechanism — it wraps an exported `.app` with a tiny native launcher that `execl`s `newtd run --game <export>`, which auto-starts the manager and hands off the correct `XR_RUNTIME_JSON`/`VK_ICD_FILENAMES`. But it requires `newt configure` to have already been run *on that exact machine*, against absolute, machine-specific paths — it's a dev-retest convenience (its own result even reports `"scope": "development Mac; requires configured Newt"`), not something that works on a player's Mac that has never heard of Newt.

Goal: make a Godot macOS export fully self-contained — bundles a developer-supplied OpenXR loader + Monado runtime + MoltenVK ICD + `newtd` itself, auto-configures into a private, app-scoped Newt state directory on first launch (never touching any system-wide Newt/Pippin install), and needs no dashboard, no Pippin, and no manual setup step by the player — plus a Godot `EditorExportPlugin` that produces this automatically from **Project → Export**, rather than a manual post-export script. Newt doesn't vendor OpenXR/Monado/MoltenVK binaries (existing "no vendored binaries" convention, `DEPENDENCIES.md`) — the developer still supplies their own locally-built copies, same as today's manual Pippin bundling; this feature only automates the bundling mechanics and the auto-configure step.

## Design

### 1. `newtd`: self-bootstrapping `run`

In `daemon/newtd.mm`, the `run` command path (`main()`) currently does `LoadConfig(paths.state)` unconditionally and fails loudly if `config.json` doesn't exist. Add: if `LoadConfig` would fail because the file is missing, and `NEWT_BOOTSTRAP_DASHBOARD` + `NEWT_BOOTSTRAP_RUNTIME` environment variables are both present, synthesize and write a `config.json` from those paths first (reusing `RunConfigure`'s existing `Executable()`/`Manifest()` validation), then proceed exactly as if `configure` had already been run. `NEWT_BOOTSTRAP_ICD` is optional, matching `configure`'s own `--icd` optionality. No wire-protocol change; this only affects the CLI's own startup, mirroring `EnsureSession`'s existing "auto-start if not already running" spirit but one level up (auto-*configure*, once, on first launch only — subsequent launches see `config.json` already exists and skip it). Implemented inside `LoadConfig`/`load_config` itself (both managers), so `serve`/`start` benefit identically and there is exactly one missing-config path; the synthesized write reuses the same temp-file-and-rename helper as `configure`.

### 2. Bundling mechanics: extend `newtd bundle`

Add to `RunBundle` (mirror in `tools/newt.py`'s `bundle()` for the reference implementation, so the acceptance suite can exercise both): new flags `--runtime PATH --icd PATH` (ICD optional) and a required `--bundle-id ID` when `--runtime` is given. When present:

- Resolve the full non-system dylib closure of the runtime/ICD's `library_path` targets and copy+relink them to `@loader_path`, under `Contents/Resources/Newt/lib/` in the *output* bundle — the same otool/`install_name_tool` chase `pippinVR-Server/bundle-monado-runtime.sh` already implements and has proven, just generalized. Port that logic (it's already a self-contained Python heredoc in that script) into a new, Newt-owned, generic tool: `Newt/tools/bundle-dylib-closure.py` (explicit source dylibs, explicit destination dir, no Pippin-specific paths/naming). `RunBundle` shells out to it at bundle time — bundling only ever runs on the developer's own Mac during export, so a Python build-time dependency here is fine (this isn't the installed session-manager CLI path removed earlier this session).
- Write rewritten copies of the runtime/ICD manifests pointing at the relocated dylibs: `Contents/Resources/Newt/runtime.json` / `icd.json`.
- Generate a trivial dashboard stub at `Contents/Resources/Newt/dashboard-stub.sh`. As designed this was `#!/bin/sh` + `"$(dirname "$0")/newtd" stop` + `exit 0`, so that once the wrapped game exits and `newtd` restarts "the dashboard," the stub shuts the whole manager down instead of lingering — there's no menu/idle experience to return to. Implementation detail: the manager also starts the dashboard *once before* the game, when `serve` first comes up, so an unconditional `stop` races (and usually wins) against the pending launch. The shipped stub therefore plays a silent dashboard on its first start per manager lifetime (blocking on stdin until the manager's graceful `stop` line, keyed by a marker file named for its parent/manager pid in `NEWT_IPC_DIR`), and only on the post-game restart — marker present, same manager pid — runs `"$(dirname "$0")/newtd" stop`. Same observable behavior, no startup race, and a failed game launch (which also restarts the dashboard) likewise leaves nothing lingering.
- Copy `newtd` itself to `Contents/Resources/Newt/newtd`.
- Extend the existing inline-compiled native launcher source (the `NewtLaunch` snippet `RunBundle` already generates and compiles via `clang`) to `setenv()` `NEWT_STATE_DIR`/`NEWT_IPC_DIR` (private, see #3) and `NEWT_BOOTSTRAP_DASHBOARD`/`NEWT_BOOTSTRAP_RUNTIME`/`NEWT_BOOTSTRAP_ICD` (pointing at the bundled copies above) before its existing `execl(newtd, newtd, "run", "--game", game, NULL)`.
- Signing stays exactly as `RunBundle` already does it: `codesign --sign ${CODESIGN_IDENTITY:--}`, ad-hoc by default — matches `bundle-monado-runtime.sh`'s existing convention, so real distribution signing already works via the same env var override, no new signing logic needed.

### 3. Private, per-app state scoping

New identifier, not the existing `org.newt.development.<stem>` (that one is explicitly for the dev-retest workflow). `NEWT_STATE_DIR` = `~/Library/Application Support/<bundle-id>/Newt`; `NEWT_IPC_DIR` = `/tmp/newt-session-<12-hex-char hash of bundle-id>-<uid>` — hashed and truncated so it stays well under AF_UNIX's 104-byte `sun_path` limit regardless of how long `bundle-id` is (the same constraint this session's own test fixtures hit with long scratch paths). This guarantees a distributed game never touches, collides with, or is affected by a separately-installed system-wide Newt or Pippin setup on the player's Mac.

### 4. Godot export automation: new `EditorExportPlugin`

New file `Newt/addons/newt_bridge/export_plugin.gd`, registered from `plugin.gd._enter_tree()` via `add_export_plugin()` (today that function only calls `add_autoload_singleton`/`add_tool_menu_item`). New project settings via the same `_setting()` helper `plugin.gd` already uses for `newt/executable` etc.: `newt/distribution/runtime_manifest`, `newt/distribution/icd_manifest` (optional), `newt/distribution/bundle_id` (default derived from `application/config/name`). These mirror the existing "Configure Newt…" dialog's fields, but for distribution rather than editor Play.

`_export_end()` — macOS only, same `OS.get_name() != "macOS"` guard `_build()` already uses — locates the just-exported `.app` and invokes `newtd bundle --game <export> --output <export dir>/<name> (Newt-ready).app --runtime <setting> --icd <setting> --bundle-id <setting>`, surfacing failures via `push_error` the same way `_build()` already does with `_decode_response`. Only activates when `newt/distribution/runtime_manifest` is actually set, so projects not using this feature see no export-time behavior change.

## Verification

- Done: `Newt/tests/session_manager_test.py` (reusing its fake-dashboard/temp-state-dir fixtures) covers the bootstrap case — no `config.json`, the three `NEWT_BOOTSTRAP_*` env vars set, `run --game` self-configures and launches with no prior `configure` call, a partial bootstrap still fails as unconfigured, and the synthesized config persists for a second launch without the variables. It also builds standalone bundles (fake runtime→dependency dylib chain + fake ICD), checks the `@loader_path` relinking, rewritten manifests, bundle identifier, and deep code signature, then launches the wrapped `.app` and asserts the game received the bundle-internal manifests, the private `config.json` uses only bundle-internal paths, the developer/test `config.json` is byte-identical before and after, and the manager socket disappears (nothing lingers) after the game exits. The `EditorExportPlugin` path itself was exercised in a real Godot 4.4 editor session: plugin load registers the distribution settings (bundle id derived from `application/config/name`), and `_export_end` produced a signed `<name> (Newt-ready).app`.
- Remaining (on-device): export `examples/godot-showcase` with `newt/distribution/*` settings pointed at this machine's existing OpenXR loader build (`pippinVR-Server/third_party/openxr-sdk/build/src/loader`) and a Monado/MoltenVK build; confirm the `EditorExportPlugin` produces a `.app` that launches standalone — no Pippin running, no prior `newt configure` — connects a Quest over USB, and that quitting the game leaves no lingering `newtd`/dashboard-stub process (`ps aux | grep newtd` empty afterward).
- Remaining (on-device, side-by-side): confirm it doesn't disturb an already-configured system-wide Newt/PippinVR install on the same machine: run both side by side, check `~/Library/Application Support/Newt/config.json` (the real one) is untouched before and after. (The suite proves the mechanism against a separate test config; the real system config is unchecked against hardware.)
